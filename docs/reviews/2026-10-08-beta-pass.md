# Beta-readiness pass — 2026-10-08

**Verdict: not ready to hand to testers with real client data yet.** The screens a tester meets every day are now
much closer to beta quality, and the blocking editing/UX defects that were reproducible are fixed and covered by
tests. The risks that decide whether it is safe to hold real legal files are unchanged and still open: backups
cannot be restored on a different computer (B01), a restore discards attachments added after the backup (B02),
and nothing has been run on Windows or macOS, the platforms the product targets. See [What still blocks a
beta](#what-still-blocks-a-beta).

Scope was agreed as "beta-blocking bugs + UI/UX". It was not the full remediation plan. Baseline for this pass:
`a6324c1`. Linux only (WebKitGTK for native runs, Chromium for screenshots). No migration was edited; one new
numbered migration was added.

## Changes

### Editing and data

- **B07** — `replace_clients` now diffs membership. Unchanged links are kept (and keep their `created_at`); a removal
  that a case relies on is refused _before any write_ with the new stable code `POWER_OF_ATTORNEY_CLIENT_IN_USE`.
  The POA dialogs now show that message instead of a fixed string.
- **B09** — completed hearings no longer show Edit or Record-decision (Agenda, case Hearings tab, and the Agenda
  `?hearing=` deep link). The agreed _correction_ of a recorded decision (P3-04) is **not** implemented.
- **B10** — migration `0002_case_judicial_year.sql` adds nullable `cases.judicial_year` (1–9999). The form keeps the
  Gregorian "Case year" (1800–9999) and adds a separate "Judicial year"; references render as «رقم 1234 لسنة 89 قضائية».
  The court-reference fields are grouped on one row. The rebuild-time search index also reads `official_year` as text
  now (it previously failed on the integer column).
- **H02** — a UNIQUE violation on a client, case or POA number is mapped centrally to `CLIENT_NUMBER_TAKEN`,
  `CASE_NUMBER_TAKEN` or `POWER_OF_ATTORNEY_NUMBER_TAKEN` (all other database failures stay opaque). Client, case, POA,
  task and hearing save dialogs show the translated, actionable message and keep the draft; an unspecific failure
  keeps the dialog's own wording («تعذر حفظ الجلسة»).
- **H03** — backup create/validate/restore use a single-flight guard (`useSingleFlight`).
- **B05 (partial)** — the Rust boundary now reads a recovery key in any case and with spaces, dashes, line breaks or
  Arabic-Indic digits; the key is shown in groups of eight, left-to-right, wrapping only between groups. Issued keys
  keep exactly the digest they always had (pinned by a test), so existing vaults still recover.
- Settings: backend validation now mirrors the database range (lock timeout 1–1440) and the form schema has the
  matching maximum.
- Copy (B13, narrowed only): reminders need the app **open and unlocked**; autostart still begins at the lock screen.
  The previous wording suggested reminders would arrive without opening the app.

### Layout, theme and shared components (found by looking at the real screens)

- **Shared `Tabs` primitive.** `orientation` was never forwarded to Base UI and every orientation selector
  (`group-data-vertical/tabs:` …) targeted attributes Base UI does not emit. Effects: the Settings tab strip rendered
  as a horizontal row overflowing its 220px column and **printed over the first settings card at every desktop size**;
  no tab list had an active-tab indicator; heights were never applied. Fixed in `src/components/ui/tabs.tsx`;
  Settings is a compact two-column grid at ≤760px.
- **Narrow windows.** Finances and Settings were 812px/800px–837px wide in a 760px window (grid blowout from a table
  `min-width` and the tab strip). `.work-page` / `.calendar-page` now use `minmax(0, 1fr)`. Measured: 0 horizontal
  overflow over 15 routes × 2 languages at 760, 640 and 480px.
- **Dark theme.** Primary fills with white text were 2.4:1. Added `--on-accent` (white in light, dark teal in dark).
  Tailwind's `dark:` variant now follows `html[data-theme]` instead of only the OS, so a "dark" setting on a light OS
  no longer yields a half-dark window. Light-mode misses (empty-value dash 2.79:1, inactive tabs 4.18/4.28:1) fixed.
- **Top-bar search.** The magnifier was drawn over the first letters of the placeholder on every page, in both
  languages (the padding rules were guarded with `:not([data-slot])`, which excludes the shadcn input).

## Decisions to review

1. **B10 differs from the register's sketch.** P3-03 describes a year-kind column and a rebuilt `cases` table. SQLite
   cannot alter a `CHECK`, and a rebuild under the migration runner's transaction (where `PRAGMA foreign_keys` cannot
   be switched off) would cascade-delete every case's children. `0002` is additive instead; legacy rows keep their
   Gregorian year. The rest of P3-03 (date handling across forms, chronology warnings) is still open.
2. **The shared `Tabs` and the `dark:` variant are global changes.** Every tab list and every shadcn `dark:` class is
   affected. They were checked on every tabbed page, but they are not local.
3. **`max-[761px]`** in the Settings tab grid is deliberate: Tailwind's `max-*` is strictly "less than", while the
   stylesheet's 760px breakpoints are inclusive and 760px is the minimum window.
4. **Visual baselines are now stale.** The 68 candidate PNGs were captured _with_ the Settings overlap and the search
   overlap. CI's visual job will fail on the changed screens until they are regenerated with
   `pnpm update:visual:canonical` (Docker) and reviewed. I did not regenerate them: the README requires a full review
   and your approval, and the matrix has no dark or narrow states.
5. The developer's name, e-mail, phone and links appear in the footer of every screen. Left unchanged; confirm that is
   intended for testers.

## What still blocks a beta

Ordered by how much they matter for real use.

1. **Nothing has run on Windows or macOS.** All native evidence is Linux WebKitGTK with the file picker stubbed.
   Installers, pickers, notifications, autostart, the macOS ad-hoc signature and WebView2 offline install are
   unverified (P7-03).
2. **B01 — backups are not portable.** A backup cannot be restored on a new computer from the password alone. Tell
   testers explicitly, or implement backup v2 (P2-01/02).
3. **B02 — restore deletes attachments added after the backup**, and the retained emergency snapshot has no
   recovery UI (P1-03).
4. **B05 remainder** — explicit copy/print/save controls and key regeneration.
5. **B09 correction** — a typo in a recorded hearing decision cannot be fixed (P3-04).
6. Open by design of this pass: B03/B14 acceptance, B04 attachment encryption decision, B12 (synchronous commands),
   B13 delivery while locked or closed, the search/finance/settings/reminder groups (P4), P5-02/03, exports,
   permanent deletion and support bundle (P6), regenerated user guides and release docs (P7-01), and the Egyptian
   privacy legal review. The generated user guides under `docs/user-guide/` still contain pre-fix screenshots and
   the old reminder wording.
7. `cargo audit` is not installed in this environment, so the dependency advisory check was not run.
